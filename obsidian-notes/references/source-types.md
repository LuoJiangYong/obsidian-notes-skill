# Obsidian 来源类型

当笔记来源不只是当前对话时，使用本文件判断如何保留来源、提取内容和标记可信度。

核心原则：

- `Key references` 是唯一外部来源区：用户 URL、本地原始文件、官方文档、API endpoint、页码、章节、sheet、slide 等都放这里。临时抽取文本、HTML 抓取件和工作区副本只作为消化过程材料，笔记完成后默认不保留引用，除非它本身是长期可复核来源。
- `文件引用` 只放 Obsidian 内部 wiki 链接，不放 URL、本地路径或 API endpoint。
- 用户提供的微信或其他平台 URL，必须同时出现在 `Context` 和 `Key references`：
  - `Context` 用于阅读时快速知道来源。
  - `Key references` 用于证据追踪和后续检索。
- 网页 URL 使用 Markdown 链接格式，链接文字优先使用内容标题、页面标题、文档标题、仓库名或平台入口名，例如 `[我们一起奔赴热爱](https://...)`；无法确认标题时才使用 `[微信原文](...)` 或 `[来源链接](...)`。不要用反引号包裹 URL；本地路径和 API endpoint 仍使用反引号。
- 不要在 `后续可复用关键信息` 中重复来源路径、URL 或页码。

## 来源处理规则

### 微信文章

适用于微信公众号文章、微信推文、保存的 HTML、截图、DOCX 草稿或复制正文。

需要捕捉：

- 标题、公众号/发布主体、作者（如有）。
- 发布时间、访问/保存时间。
- 用户提供的原始 URL 或本地导出路径。
- 关键主张、案例、数据、框架和可复用方法。
- 如果页面无法完整读取，要说明访问限制。

规则：

- 如果用户提供了原始 URL，`Context` 中必须保留该 URL，并写成可点击 Markdown 链接。
- `Key references` 中必须保留 URL 或本地导出文件路径；URL 写成 Markdown 链接，本地路径用反引号。
- 不要大段引用原文；必要时只保留短摘录，其余用总结和结构化整理。
- 当同时存在微信 URL 和本地 DOCX/PDF/截图/图片原稿时，微信 URL 是正式发布源，本地文件是辅助校验源。笔记主题仍按微信推文整理，不要改写成内部文档整理。
- 本地 DOCX、截图目录和图片文件如作为长期校验源，可放入 `Key references`；临时抽取文本和工作区副本默认不写入笔记，完成消化后应清理。
- 图片型微信稿要区分正式正文、图片识别内容、设计备注和排版备注。原稿中的“配图”“排版说明”“找图”等设计备注不要误写成已发布事实。

#### 微信 URL + 原稿/截图混合来源

处理顺序：

1. 先记录微信标题、公众号、发布时间、URL、访问/保存时间；URL 使用文章标题作为链接文字，例如 `[我们一起奔赴热爱](https://...)`。
2. 再读取 DOCX/PDF/截图/OCR 文本作为校验来源。
3. 用原稿章节结构重建正文，保留主线、事实、数据、机制和案例。
4. 在 `Context` 说明主来源和辅助来源的关系。
5. 在 `Key references` 同时保留微信 URL、原始文件路径和必要的图片目录；临时抽取文本路径默认不保留。

可信度：

- 只读取微信 HTML 且正文完整：通常可为 `validated` / `high`。
- 只靠截图 OCR 或 vision 识别：使用 `captured` 或 `needs-review`，`confidence` 为 `medium` 或 `low`。
- 已直接读取 DOCX/PDF/原始正文并完成校正：可提升为 `validated` / `high`。
- 如果有图片未识别、GIF 只读首帧或 OCR 明显不完整，必须在 `Context` 或 `Key references` 说明，不要用完全确定的语气覆盖不确定性。

### 普通 URL / 网页

适用于普通网页、在线文档、博客、产品页、新闻稿和线上报告。

需要捕捉：

- 页面标题、发布方、作者（如有）。
- 发布/更新时间和访问时间。
- 精确 URL。
- 事实主张和整理者推断要区分。
- 长网页要标记使用了哪些章节。

规则：

- 用户提供的 URL 必须出现在 `Context` 和 `Key references`，并写成 Markdown 链接。
- 如果当前准确性重要，需要实时验证网页内容。

### PDF

适用于报告、白皮书、扫描文件、手册、宣传册和导出的 slides。

需要捕捉：

- 本地路径或来源 URL。
- 文件名、页数（如可得）。
- 关键事实对应的页码或页码范围。
- 图表/表格名称和数据限制。
- OCR 或图片型页面的识别限制。

规则：

- `Key references` 中保留原始 PDF 路径和关键页码。
- 页码是证据，不是正文替代。正文必须整理出完整内容和机制。

### DOCX

适用于 Word 文档、方案、计划、总结、会议材料和草稿。

需要捕捉：

- 本地路径、文件名、版本/日期（如有）。
- 标题结构和使用章节。
- 评论、修订或批注（如与任务相关）。
- 核心决策、行动项、可复用表达和未解决问题。

规则：

- 如果存在多个版本，要保留版本语境。
- `Key references` 中保留文件路径和关键章节。
- 如果 DOCX 是微信推文、公众号长图或发布稿的原稿，它是校验源，不自动替代微信 URL 的正式发布源。
- 如果 Word 原稿含有设计、配图、排版备注，整理正文时要标记或剔除这些备注，避免把制作说明当成最终发布内容。

### EXCEL / 表格

适用于 Excel 工作簿、CSV、KPI 导出、运营数据表和分析表。

需要捕捉：

- 本地路径、工作簿名、使用的 sheet。
- 时间范围、行列范围、字段定义、指标公式。
- 筛选条件、透视/聚合方式和数据限制。
- 关键表格或汇总，不要直接倾倒整张表。

规则：

- 必须说明指标定义和分母假设。
- 不要把原始表格泛化成空洞文字，要保留数据颗粒度。

### PPTX / Slides

适用于演示文稿、工作汇报、策略 deck、培训材料和活动方案。

需要捕捉：

- 本地路径、deck 名称、slide 数量（如可得）。
- 使用的 slide 编号或章节标题。
- 主线叙事、关键主张、数据图表、案例和决策。
- 需要保留的视觉资产或图示。

规则：

- PPTX 往往有强叙事结构，先保留 storyline，再提取细节。
- `Key references` 中保留文件路径和关键 slide/章节。

### 已有 Obsidian 笔记

适用于更新、总结、拆分或综合 vault 中已有笔记。

需要捕捉：

- 原笔记标题和路径。
- 新笔记是总结、修正、扩展还是索引原笔记。
- 内部关系放入 `文件引用`。
- 本地路径只有在对 Agent 迁移有帮助时才放入 `Key references`。

### 当前对话

适用于当前聊天是主要来源的情况。

需要捕捉：

- 用户意图、已做决策、执行过的工具、改动过的文件、验证状态。
- 关键路径、命令、端点和约束。
- 如果确实存在待办或后续行动，再写行动项；不要默认生成 `Next actions`。

## 可信度判断

- `high`：本次运行直接读取来源，或写入后读回验证，或来源可靠且已核对。
- `medium`：来自对话上下文、记忆、部分文件检查或间接材料。
- `low`：来源不完整、不可访问、OCR 受限、图片识别不全或尚未验证。

可信度升级规则：

- 从截图/OCR/vision 得到的内容默认不能直接标为 `validated` / `high`。
- 只有在直接读取正式网页正文、DOCX/PDF 原稿、可复制文本或写入后读回核验时，才可提升为 `validated` / `high`。
- 如果只能读取元信息，正文不可抽取，状态应为 `needs-review`，并在正文说明缺口。

## Windows 中文路径处理

Windows 环境中，Python 或部分文档解析库可能无法直接读取含中文用户名、中文文件夹或特殊符号的路径。

处理规则：

1. 先用 PowerShell `Test-Path` 或 `Get-Item -LiteralPath` 确认原始文件存在。
2. 如果解析库读取失败，可把文件复制到工作区英文短路径作为临时解析副本。
3. `Key references` 保留原始路径；工作区副本只作为解析中间件，不替代原始来源身份。
4. 笔记完成后默认不保留工作区副本路径，并在确认不再依赖后清理副本。
5. 不要因为解析失败就降级为轻量摘要；应先尝试可访问副本、导出文本或其他结构化读取方式。

## Key references 要求

| 来源 | 必需引用 |
|---|---|
| 微信文章 | Markdown 链接格式的 URL 或本地导出、公众号、发布时间/访问时间（如可得） |
| URL | Markdown 链接格式的 URL、标题/发布方、访问时间 |
| PDF | 路径或 URL、文件名、关键页码范围 |
| DOCX | 路径、文件名/版本、使用章节 |
| EXCEL | 路径、工作簿、sheet、指标定义 |
| PPTX | 路径、deck 名称、slide 编号或章节 |
| 已有 Obsidian 笔记 | 内部关系放 `文件引用`；仅必要时在 `Key references` 放路径 |
| 当前对话 | 不虚构引用；只放实际存在的文件、工具输出或路径 |
